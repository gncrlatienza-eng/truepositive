# Full audit — 2026-10-04

Scope: backend (FastAPI), frontend (React/Vite), Windows agent + installer, Docker/Caddy/nginx, and CI. The audit was a read-only sweep followed by targeted verification of each finding against the code. Fixed items are listed with where the fix lives; everything else is open, in rough priority order.

**Good news first:** no cross-tenant IDOR was found (every by-id lookup is scoped to `org_id`), no raw/interpolated SQL, no SSRF surface (threat intel is a static feed), no path traversal in the download endpoints, and no `dangerouslySetInnerHTML` (log content is rendered as text).

Also in this pass: the frontend's host port moved **3000 → 3100** so TruePositive and the separate Bantai project (whose NestJS backend uses 3000) can run at the same time. Only the host side changed; inside the container nginx still listens on 3000.

## Fixed

### Critical
| Finding | Fix |
|---|---|
| `.gitignore` had `agent_config.jsont ` (typo + trailing space), so the agent credential file was no longer ignored | Restored `agent_config.json` |
| **Local privilege escalation via the agent's pre-authorized Scheduled Tasks.** The `/RL HIGHEST` tasks ran `truepositive-agent.exe` from per-user `%LOCALAPPDATA%`, so any process running as the user could swap the exe and `schtasks /Run` it to get admin with no prompt | Elevated actions are now fixed PowerShell scripts (`agent/elevated/*.ps1`). The installer copies them into `%ProgramFiles%\TruePositive\elevated` (only admins can write there), and the tasks run them from that folder. The `--elevated-action` exe path is gone |

### High
| Finding | Fix |
|---|---|
| Sysmon was downloaded to a predictable user `%TEMP%` path, then signature-checked and executed elevated, so it could be swapped in between (TOCTOU) | Download, check and install all happen inside a fresh admin-only folder under `%ProgramFiles%\TruePositive\work` (`install_sysmon.ps1`) |
| The UAC fallback ran `inner.ps1` from a user-writable temp folder, so it could be rewritten while the prompt was on screen | The script text is passed inline via `-EncodedCommand`, with no file on disk (`_run_elevated_fallback`) |
| The elevated step wrote its results into the user-writable app folder (a junction there could redirect an elevated write) | Results go to `%ProgramFiles%\TruePositive\results` (admins write, users read). The agent accepts a result only if it finished after the attempt started |
| Apostrophes in paths/usernames broke out of PowerShell strings | All interpolated values go through `_ps_quote` |
| Behind Caddy, every request appeared to come from the proxy IP, so 10 bad logins/min locked out every user | `FORWARDED_ALLOW_IPS="*"` in `docker-compose.prod.yml` only (the backend isn't published there). nginx now overwrites `X-Forwarded-For` |
| The rate limiter kept every key forever, so a loop of junk agent ids grew memory without bound | `deque` buckets plus a periodic sweep of idle keys; agent-id keys must be real UUIDs (`rate_limit.py`) |
| An expired *pending* enrollment key still worked for `/heartbeat`, `/logs` and `/sources`, flipping the agent to connected | `get_current_agent` now returns 410 for expired pending keys (`enrollment_expired`) |
| Unthrottled bcrypt on `/agents/{id}/sources` and `/sources/status`, plus a timing oracle for unknown agent ids | Both endpoints are rate-limited; unknown ids now run a dummy bcrypt |
| Scheduled reports covered the wrong period (today at 00:15, i.e. ~15 minutes) | `ref_date` is now yesterday (`report_scheduler.py`) |
| A 255-character rule name overflowed `Alert.title`, which rolled back the whole batch, and the agent retried it forever | Title truncated to 255 (`log_service.py`) |
| The dashboard rendered blank (unhandled rejection) when the first load failed | Error state with a "Try again" button (`DashboardPage.jsx`) |

### Medium (quick fixes)
- **Input bounds**
  - Log message capped at 32k chars and `raw` at 64KB.
  - Relay `logs` / `source_status_results` capped at 500, so oversize payloads get a 422 instead of a 500.
  - Intel lookup and link values need 3–255 chars.
  - Custom report ranges must have `start ≤ end` and span at most 366 days.
- **Wildcard search:** `%` and `_` in intel searches are escaped, so `_` no longer matches every log. Lookup counts are now aggregated in SQL instead of loading every matching row.
- **Explicit `null` in PATCH bodies** now returns 422 instead of 500, via `reject_explicit_nulls` on incidents, playbooks, alert rules, alerts and log sources.
- **Negative `limit`/`offset`** now returns 422 on `/logs`, `/alerts`, `/incidents` and `/reports`. The `/reports?type=` filter is validated as an enum.
- **Incident create** checks that the assignee belongs to the org, the same check update already did.
- **Report schedule emails** are validated as `EmailStr`, which rejects CR/LF header injection. `send_email` also catches `ValueError`.
- **Signup invite code** is now compared in constant time. A short `JWT_SECRET` logs a warning.
- **APScheduler** jobs get an hour of misfire grace and are coalesced, so a restart at 00:15 no longer drops that night's run.
- **Docker images**
  - New `.dockerignore`, so the host `.venv`, `node_modules` and `.env` stay out of images.
  - The frontend image uses the lockfile (`npm ci`) on Node 22.
  - The backend runs as a non-root user.
  - nginx sets `server_tokens off`.
  - Caddy adds HSTS, strips `Server`, and limits request bodies to 20MB.
- **CI** now runs the agent tests (Windows runner) and sets `permissions: contents: read`.
- **Frontend**
  - Logout clears the per-user IOC lookup history.
  - The landing-page reveal/parallax hooks clean up their timers and animation frames on unmount.
- **Cleanup:** removed the empty path-mangled folders `Caddyfile;C` and `frontend\src;C`.

## Open — not fixed in this pass

### High / needs a design decision
- **Hub relay listener** (`tp_agent.py`, `0.0.0.0:47824`):
  - No authentication, no TLS, and no request body cap (`rfile.read(Content-Length)`).
  - Child keys cross the LAN in clear text.
  - Any LAN host can use up the hub's 120/min backend quota.
- **Session tokens** (overlaps with SECURITY.md gaps):
  - The JWT lives in `localStorage` for 30 days.
  - There is no CSP.
  - Logout is client-side only.

### Medium
**Frontend data loading**
- No `AbortController` or request-id guards on any fetch, so stale responses can overwrite newer ones:
  - `AlertsPage`
  - `LogsPage`
  - `IncidentsPage`
  - `GlobalSearch`
  - `ReportsPage`
  - `IncidentDetailModal`
- The incident SLA-breach filter runs on one page of results on the client, which breaks pagination.
- `IncidentDetailModal` fetches each linked alert's log separately (N+1), and the link picker caps at 200.

**Backend performance (N+1 and full-table loads)**
- During ingestion, one playbook query runs per log (up to 500 per batch).
- `_to_out` runs one count query per incident (up to 5,000 for CSV export).
- One count query runs per MITRE technique.
- `dashboard_service` loads all triage deltas, and `report_service` loads all incidents.

**Report delivery and scheduling**
- `GET /reports/generate` sends email synchronously, up to 10s SMTP timeout per schedule.
- `ReportSchedule.frequency` is never read.
- There's no unique constraint on `(org_id, type, period_end)`, so concurrent generation can create duplicates.

**Data and keys at rest**
- A rotated key on a connected agent stays decryptable at rest until the next register.
- Migrations have drifted from the models:
  - `incidents.assignee_id` ON DELETE.
  - The reports/schedules CASCADE.
  - The tests use `create_all`, so migrations are never exercised.

**Agent**
- Embedded/CLI `--key` exposure.
- The GUI log widget grows unbounded.
- `readline()` has no size limit.
- Threads abandoned after a timeout pile up.
- The `Global\` mutex blocks a second Windows user.

**Bundle and dependencies**
- No code-splitting: the landing page downloads the whole app plus map/chart libraries. `UnderWatchHero` re-projects the world map on every frame.
- Dependencies:
  - `python-jose` is effectively unmaintained; move to PyJWT.
  - Upgrade `cryptography` to ≥ 44.0.1 (CVE-2024-12797).
  - FastAPI 0.115.0 pins an old Starlette.
  - Vite 5 is EOL, and esbuild 0.21 carries the dev-server advisory GHSA-67mh-4wv8-2f99.
  - `pytest`/`httpx` ship in the production image.
  - `playwright` is an unused devDependency.

### Low / code structure
**Low-severity issues**
- Login timing reveals which emails exist.
- Emails aren't case-normalized.
- `/docs` and `/openapi.json` are public in prod.
- Roles are never enforced (fine while signup only creates admins).
- Expired whitelist entries can't be re-added (409).
- Naive and future-dated ingestion timestamps are accepted.
- Decrypt failures in `GET /agents` cause a 500.
- Changing the primary agent orphans relay children.

**Code structure**
- Large files worth splitting:
  - `tp_agent.py` (~2.2k lines)
  - `IntelPage.jsx`
  - `ReportsPage.jsx`
  - `LandingPage.jsx`
  - `UnderWatchHero.jsx`
- Six copies of the blob-download helper.
- Routers that do service/DB work (`settings.py`, `reports.py`, `incidents.py` CSV, `agents.py` downloads).
- Duplicated severity/SLA constants.
- Dead `/ping` routes and an empty `app/middleware/`.
